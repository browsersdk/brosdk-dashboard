# 跨境电商方向验证

Commerce 是 BroSDK Dashboard 1.0 之后的可选垂直模块，不属于当前多环境控制中心的正式发布范围。现阶段不建设传统 ERP，也不同时开发多个平台连接器。

## 验证假设

需要先证明：

1. 用户确实希望把店铺账号与浏览器 envId 建立稳定绑定。
2. 一键打开店铺后台、查看登录状态和处理异常，比单纯环境列表更有价值。
3. 至少一个平台的只读订单同步能明显减少用户切换多个后台的成本。
4. 用户愿意接受平台 OAuth/API 授权、数据新鲜度和本地隐私边界。

如果这些假设没有真实使用数据支持，不继续扩展库存、商品刊登、仓储和财务。

## C1：店铺工作区

店铺是独立的本地业务 overlay：

| 字段 | 归属 |
| --- | --- |
| storeId、平台、店铺显示名、备注 | 本地工作区事实 |
| 绑定 envId | 本地关系，引用服务端环境 |
| 环境名称、指纹、代理、内核 | SDK 服务端事实 |
| 当前运行和登录检查 | DLL/runtime 事实 |

最小能力：

- 店铺列表、平台筛选、备注和绑定 envId。
- 一键启动或打开绑定环境中的平台后台。
- 显示环境是否存在、是否运行以及最近登录检查时间。
- 环境被服务端删除后保留店铺记录并明确显示绑定失效。

不保存店铺后台密码、Cookie 明文或平台 token。

## C2：单平台只读订单

只选择一个有真实测试账号和明确授权条件的平台：

- connector 只实现授权刷新、订单分页拉取和同步状态。
- 平台订单是事实来源；本地只保存最小脱敏快照、新鲜度和失败原因。
- 默认不保存买家完整地址、电话、邮箱或付款信息。
- API 不可用时可以打开绑定环境的后台，但不把人工操作伪装成同步成功。

这一阶段不做物流回传、库存写入、价格修改和商品刊登。

## 数据所有权

Commerce 不能使用“所有本地数据都是缓存”的笼统规则：

| 数据 | 事实来源 |
| --- | --- |
| 店铺到 envId 的绑定、备注和本地工作流状态 | 本地或未来业务服务 |
| 平台订单、listing 和平台库存 | 平台 API |
| 统一 SKU、映射和运营策略 | 如果后续建设，由业务服务作为事实来源 |
| 发货草稿 | 本地/业务服务，平台确认后记录外部状态 |
| OAuth/token | 平台授权服务，密钥进入安全存储 |

如果进入多用户、Webhook、库存写入或发货回传，必须先建设独立业务服务，不能把桌面 SQLite 当成团队 ERP 数据库。

## Agent 边界

- Chat 只能读取脱敏店铺和订单摘要。
- 打开后台可以复用受控 navigate；点击、输入和提交仍按高风险工具审批。
- Agent 不能持有平台 token、店铺密码、买家隐私、API Key、userSig 或完整 CDP URL。
- 每次动作关联 storeId、envId、operation 和审批来源。

## 继续或停止的门槛

只有同时满足以下条件才进入物流或库存方向：

- 至少一个真实平台 connector 连续稳定运行。
- 有真实用户持续使用店铺工作区和订单聚合。
- 隐私、授权、限流、重试和数据删除流程已经验证。
- 明确需要桌面模块还是独立云端产品。

否则 Commerce 保持为店铺快捷工作区，不扩张为 ERP。
