# 正式发布路线

本路线只描述尚未完成的产品工作。阶段 0-34、内核 catalog 与安装修复等历史实施记录已归档到 [历史实施记录](history/implementation-history.md)。

## 目标

把当前 0.1.0 Windows 内测版建设成可靠、易懂、可维护且可正式分发的多环境指纹浏览器控制中心。1.0 前不扩张为完整 ERP，也不承诺没有动态库和真实验收的 macOS/Linux。

## 总体顺序

| 里程碑 | 目标版本 | 重点 | 出口条件 |
| --- | --- | --- | --- |
| R1 发布基线 | 0.2 | 安全、版本、签名、更新和风险控制 | 可以安全交给外部测试用户 |
| R2 运营效率 | 0.3 | 大规模环境组织、批量创建、Cookie 和扩展 | 日常管理不依赖开发者工具 |
| R3 发布候选 | 0.9 | 稳定性、规模、迁移、兼容和体验收口 | 完整 RC 门禁通过 |
| R4 正式发布 | 1.0 | 签名交付、支持策略、隐私许可和发布自动化 | 可重复发布和回滚 |
| C1 Commerce 验证 | 1.0 之后 | 店铺工作区和单平台只读 connector | 有真实用户数据再决定是否扩展 |

## R1：发布基线

目标：解决“能运行”与“可以交给外部用户”之间的差距。

### 安全

- 为 Tauri 配置最小 CSP，只允许应用本地资源和所需 IPC；AI Provider 网络请求继续由 Manager 发起。
- 将 AI 会话从 WebView localStorage 迁入 Manager，使用平台保护或提供默认不持久化模式。
- 建立 MCP/Agent 工具风险等级：
  - 只读：状态、tabs、read、snapshot 等，可在 Chat 和自动模式使用。
  - 低风险写：navigate、wait 等，只在 Agent 自动白名单中使用。
  - 高风险写：act、evaluate、upload、download、表单提交和文件操作，每次明确批准。
- 对文件选择、下载和上传增加目标路径、大小、扩展名与脱敏审计边界。
- 完成公开分发前的 DLL 再分发许可和项目许可证确认。

### 发布工程

- 建立单一版本来源并同步 Cargo、npm、Tauri、安装器和发布清单。
- 定义 DLL 版本兼容矩阵；启动时报告客户端、Host、头文件 ABI 和 DLL 版本。
- 接入代码签名，正式渠道签署 Dashboard、sdk-host 和安装器；第三方 DLL 校验供应方签名、版本和固定摘要，不由客户端重新签名。
- 设计稳定更新通道、失败回滚和数据库迁移备份；不把覆盖安装当作更新策略。
- 将 release verify、安装/卸载、托盘、单实例和首次初始化纳入发布流水线。

### 可靠性

- Host 崩溃、锁冲突、MCP 失联和网络中断都必须在有限时间内收敛到明确状态。
- 长时间运行、托盘恢复和客户端重启后重新对账，不保留遗留 starting/ready。
- operation 必须有终态或明确超时；不能无限显示“执行中”。
- 建立脱敏诊断包，包含版本、能力、状态时间线和错误码，不包含密钥、Cookie、页面正文或完整 URL。

验收：

- 安全检查、全量自动化、真实环境 E2E 和签名安装包验证通过。
- 新安装、覆盖升级、失败回滚和卸载都不会丢失受支持的本地设置。
- 自动 Agent 无法绕过风险等级调用高风险工具。

## R2：运营效率

目标：让管理几十到几百个环境的用户不需要依赖 MCP 控制台或逐个操作。

### 环境组织

- 增加独立本地 overlay：分组、标签、收藏、备注和保存筛选。
- overlay 只以 envId 关联，不覆盖服务端名称、指纹、代理或内核。
- 支持按状态、代理、内核、分组和最近运行时间组合筛选。
- 工作台显示最近使用、运行中、失败和需要更新的环境。

### 批量工作流

- 支持代理批量导入、校验和去重。
- 支持从代理集合与已安装内核批量创建环境，逐环境 operation 和补偿清理。
- 批量启停继续保持每个 envId 独立状态，提供失败项重试和结果导出。
- 对高数量环境增加虚拟列表、分页或增量渲染，并验证 100/500 环境性能。

### 会话与运行资源

- 接通 sdk_env_get_cookies，提供受保护的 Cookie 查看、导入和导出。
- 明确 Cookie/Storage 文件格式、加密、覆盖策略、冲突提示和审计边界。
- 增加本地扩展扫描、manifest 校验、版本展示和按环境启动选择。
- 保留普通创建的“代理 + 内核”两字段流程，高级能力放入环境详情或批量向导。

### 信息架构

- 已将九个开发期一级入口收敛为工作台、环境、自动化、资源和系统。
- MCP 控制台、SDK 自检、操作原始信息进入系统区域，并通过组内标签访问。
- 普通状态使用“运行中、已停止、安装中”等产品语言；CDP、reqId、generation 只在详情与诊断中出现。

验收：

- 新用户可以在不理解 DLL/MCP/CDP 的情况下完成初始化、创建、启动、停止和故障恢复。
- 100 个环境下搜索、筛选、选择和批量操作保持可用，500 个环境下不出现不可接受的阻塞。
- Cookie、扩展和批量创建都有失败补偿、敏感数据保护和真实环境 E2E。

## R3：发布候选

目标：冻结 1.0 功能范围，通过稳定性和兼容性门禁。

- 冻结服务端、DLL、Manager、Dashboard 和本地数据库兼容矩阵。
- 覆盖 Windows 10/11、WebView2 缺失/旧版本、普通用户权限和非 ASCII 路径。
- 执行长稳测试：多轮启停、网络抖动、Host 重启、睡眠唤醒和托盘驻留。
- 验证数据库从所有受支持旧版本迁移，并能在更新失败后恢复。
- 完成中文界面术语统一、键盘操作、焦点、屏幕阅读器标签和缩放测试。
- 建立用户可理解的错误码、支持文档和诊断包收集流程。

验收：

- 所有 P0/P1 发布缺陷关闭。
- RC 安装包完成签名、升级、回滚和真实账号回归。
- 连续运行和规模测试没有状态漂移、进程残留或敏感信息泄漏。

## R4：正式发布

目标：形成可重复、可支持的 1.0 发布。

- 发布签名 NSIS 安装包和便携 ZIP；MSI 根据企业用户需求决定是否正式支持。
- 发布 SHA-256、版本说明、支持的系统/DLL 矩阵、已知限制和回滚说明。
- 明确隐私政策、日志与 AI 数据边界、许可证和 DLL 分发条款。
- 发布流水线从干净环境构建、测试、签名和验证，不依赖维护者本机缓存。
- 建立稳定版与预览版通道，以及紧急回滚流程。

## C1：Commerce 验证

Commerce 不进入 1.0 核心范围。正式版稳定后，只做一个小范围验证：

1. 店铺工作区绑定现有 envId，提供平台入口、登录状态、备注和一键打开后台。
2. 选择一个平台接入只读订单同步，不同时建设 Amazon、Shopify、eBay 和 TikTok Shop。
3. 只展示订单新鲜度和异常，暂不建设统一库存、刊登、财务或仓储。
4. 根据真实使用频率、授权成本和数据合规结果决定继续、独立成模块或停止。

详细边界见 [跨境电商方向验证](commerce-roadmap.md)。

## 不进入当前路线的事项

- 完整 ERP、采购、财务、仓储和利润核算。
- 未有对应动态库与真实发布验证的跨平台承诺。
- 默认创建页的完整指纹编辑器。
- 绕过平台 API、授权或风控的浏览器自动化。
- 无风险等级、无 operation、无审计的 AI 自动写操作。
